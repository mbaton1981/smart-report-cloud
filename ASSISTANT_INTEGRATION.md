# Интеграция помощника: ревизия и границы

## Что было в 1.0.27-rc3

Маршрутизатор выбирал одну функцию просмотра смен. Проверки транспорта,
сохранённых цен и дублей существовали, но контекст между запросами не
передавался. Зарплатный/клиентский PDF и просмотр применения цен вызывали
штатные функции. Голос давал редактируемый текст без автоматического
выполнения. Справочники, баланс, расходы, карточки и остальные окна не были
доступны из диалога. Основной экран смешивал рабочие результаты с настройками.

## Единый рабочий интерфейс

- Переписка, текст, микрофон, период, сотрудник, фирма и объект.
- Выбор сохраняется только в текущем окне диалога и очищается новым диалогом.
- В OpenAI передаются команда и последняя разрешённая выборка
  (действие/даты/имена/вопрос), не содержимое базы или карточек.
- Частичные имена разрешаются на сервере по настоящему справочнику.
  Неоднозначность вызывает вопрос с вариантами, а не выбор первой записи.
- Таблицы без служебных ID. Можно открыть выбранную строку для чтения.
- Диагностика, журнал действий и API/лимит вынесены в отдельное окно.
- Последовательность из 2–4 чтений/проверок/подготовки отчётов выполняется
  на одной серверной транзакции чтения. Результаты каждого шага сохраняются
  в окне. Открытие редакторов цепочкой запрещено.
- Для PDF автоматически вызывается штатный предпросмотр; сохранение/печать
  выполняются в нём. Перед PDF сверяются локальные и серверные записи/цены.

## Реестр функций

Единый источник истины — [assistant_actions.py](assistant_actions.py).
Сервер сообщает возможности через `/api/assistant/capabilities`.
Диспетчер не вызывает произвольные методы по строке, полученной от модели.

| Раздел | Реально подключено | Что не означает |
|---|---|---|
| Смены/часы | Поиск, итоги по людям, детали строки, открытие формы новой смены | Форма не сохраняет смену сама |
| Проверки | Дубли/нет клиентской ставки, сохранённые цены/время, транспорт | Предупреждение — не доказанная ошибка; дубль не удаляется |
| Справочники | Сотрудники без реквизитов, фирмы/объекты/цены, штатный раздел редактирования | Нет автоматического изменения справочников |
| Карточки | Защищённая карточка конкретного сотрудника, штатный PDF бухгалтеру | Реквизиты не попадают в чат или модель |
| Зарплата/OB | Штатный зарплатный PDF и окно истории/корректировок | Нет новой формулы зарплаты, массового подтверждения или выплаты |
| Баланс | Чтение текущего локального профиля, история периода, текущий итог за всё время | Баланс не пересчитывается из смен и не синхронизируется как серверный |
| Расходы | Чтение сохранённого локального журнала по штатному периоду | Не запускает автоматические налоги/FORA |
| Документы расходов | Переход к штатному разделу с периодом | OCR, распределение, удаление и отметки оплаты требуют действий в штатных формах |
| Клиентские отчёты | Штатный клиентский PDF и PDF журнала работ по разрешённому объекту | Нет новой фактуры или изменения статуса выставления |
| Клиентские цены | Штатный просмотр замены цен, прежняя защита ручных/закрытых/Fast pris | Нет автоматического массового применения |
| Закрытие периодов | Переход к соответствующему объекту/периоду в штатном разделе | Не закрывает и не открывает период по команде |
| Почта | Входящие, если включены в профиле; подготовка PDF-письма с отдельным подтверждением | Почтовая очередь в текущей программе отключена и не предлагается как рабочая функция; SMTP может быть не настроен |

## Права и безопасность

Существующая интеграция остаётся доступной личному входу администратора.
Права бухгалтера/работника автоматически не расширяются. Их отдельные
существующие интерфейсы остаются без изменений; полноценный помощник с
разными областями видимости для этих ролей ещё не реализован.

Сервер проверяет HTTPS, токен/роль, dataset, выключатель, допустимое действие
и уникальность операции. Секреты не возвращаются клиенту/модели.
Сохранение карточки и экспорт повторно проверяют права штатным CardClient.
Контекст от клиента валидируется как данные, не используется как SQL или
инструкция для исполнения. Все чтения SQL параметризованы.

Кнопки и распознанные простые транспортные запросы не требуют OpenAI.
Платные запросы/голос проходят прежнее резервирование общего лимита.
Достижение лимита останавливает новые запросы к провайдеру; учёт работает.
Журнал не содержит текстов команд, реквизитов и результатов расчётов.

## Что ещё не реализовано — не выдавать за полный доступ

1. Универсальный API `preview → confirm → apply` для изменений смен,
   справочников, баланса, расходов, выплат и удаления. Текущие native-переходы
   открывают формы, а не исполняют эти изменения за пользователя.
2. Общая отмена/компенсация выполненных изменений. Действуют только правила
   соответствующего существующего раздела.
3. Ролевой помощник бухгалтера/работника с серверной фильтрацией каждого
   результата. Сейчас включён только администратор.
4. Продолжение прерванной уточнением многошаговой цепочки с сохранением
   всех ещё не выполненных шагов. Одиночный уточняемый шаг сохраняет выбор;
   после уточнения сложную цепочку следует запросить заново.
5. Автоматическая обработка неограниченных задач, фоновая отправка и
   произвольное выполнение кода/SQL. Они намеренно не допускаются.

Поэтому эта версия — интегрированный инструмент чтения/проверок/отчётов и
штатных форм, **не завершённая реализация требования обо всех пользовательских
операциях**. Нельзя считать её готовой только по соединению с OpenAI.

## Проверки и эксплуатация

Автоматические проверки используют изолированные синтетические базы:
`python -m unittest discover -s tests -p "test_*.py"` через существующий
защищённый QA runner. Свободные фразы следует отдельно проверять реальным
OpenAI на сервере, не передавая ключ в локальную среду.

Контрольные сценарии: сводка недели; транспорт прошлой недели; дубли/нет
ставки; отчёт по неполному названию объекта; другой объект/тот же период;
вопрос с выбором; цепочка проверок; голос → текст → отдельное выполнение;
выбор результата/детали; неизменность финансовых таблиц; запрет роли и
неподдерживаемого действия. Наличие синтетического теста не доказывает
успешную работу живой модели/физического микрофона/принтера.
