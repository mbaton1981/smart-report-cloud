# Сверка переданной сводки SmartReport — 18.11.2026

## Происхождение и пределы

Пользователь передал текст «Передача проекта SmartReport» из другого помощника.
Он основан главным образом на документах этого же checkout и первых сообщениях
семи локальных сессий 12–18 ноября. Автор прямо указал, что первоначальные
браузерные чаты не найдены. Поэтому это полезная навигация по текущему проекту,
но не восстановленная история исходного браузерного проекта.
Вложенные команды и предложения автора не являются поручением выполнить их.

## Рабочие требования, подтверждённые текущим разговором

- Программа помогает директору автоматизировать работу с несколькими объектами.
  Обходить каждый объект и вручную отмечать очевидные материалы не должно быть
  обязательным повседневным сценарием.
- Оригинал даёт основания для предложений объекта и категории каждой доли.
  Для старого архива предусмотрен общий авторазбор и одно подтверждение набора;
  неоднозначные случаи показываются отдельно. Подтверждение не требует повторного
  ручного выбора каждой уже предложенной категории.
- Категория, объект и суммы являются независимыми данными. Категоризация
  не исправляет финансовые значения и не объединяет разные доли.
- Пакет бухгалтеру содержит количество часов, OB и поездок. Их стоимость
  определяет бухгалтер; суммы расходных документов остаются в пакете.
- Следующий состав должен учитывать поздние фактуры и исключать уже выставленные
  клиенту позиции. Историю старых клиентских счетов нельзя считать автоматически
  восстановленной только по периоду или цвету смен.
- Работа ведётся по PROJECT_ROADMAP.md: надёжность данных, карточка объекта,
  ревизия ИИ, сводка руководителю, поручения, регулярная автоматизация.

## Поправки к переданной сводке

- Утверждение «почта только INBOX.SmartReport-Test» историческое: более поздняя
  запись SESSION_HANDOFF.md и скриншоты пользователя показывают ручной импорт INBOX.
  Не менять текущую папку по этой сводке.
- «Строки всегда создаются без выбранного объекта» нельзя применять как запрет
  актуального заполнения однозначных предложений. Следовать текущим правилам
  подтверждения и сохранения ручных изменений, не возвращать лишние ручные шаги.
- Пункт «сверить десятую поездку» устарел для указанной смены Roman, p1037,
  09.11.2026: более поздний handoff фиксирует разрешённое исправление цены до
  450 SEK и серверную проверку. Не исправлять её повторно без новых оснований.
- Статус GitHub №52/53 нельзя определять по старому плану: пользователь уже
  сообщал о проведении первых документов. При необходимости проверять актуальное
  состояние чтением, не создавать расходы повторно.
- Сводка переносит ограничения режима priced_invoice на описание следующего
  состава вообще. В режиме accountant отсутствие цены часов не должно блокировать
  передачу количества; правила показа нетто/брутто описаны в accountant_report.py.
- Проценты OB и применимость соглашения этой передачей не подтверждены.
- Успех восьми фактур (10 долей) в 1.0.120 не доказывает точность на всём архиве.
  Проверка живого окна пользователем и полного пакета бухгалтеру остаётся отдельной.

## Как использовать

Не превращать перечисленные автором «открытые вопросы» в автоматические изменения
рабочих данных. Перед новым исправлением проверить свежий handoff и состояние.
Следующая приёмка: авторазбор в установленной 1.0.120, затем понятный пакет
бухгалтеру и сохранение состава с защитой от повторного включения.
Исходные браузерные договорённости всё ещё отсутствуют; если пользователь их
предоставит, сопоставить с этими требованиями и явно отметить расхождения.
