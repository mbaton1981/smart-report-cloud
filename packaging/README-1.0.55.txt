SmartReport 1.0.55 - Windows x64

Upgrade the existing application folder, keep the approved-profile shortcut
and preserve SmartReport-1.0.9. Do not start a fresh profile.

Employees use the familiar form: object/date, ordinary hours or the existing
OB/overtime input and transport. No new start/end, break, customer mode or
Calculate hours editor is required. Previously saved detailed intervals are
retained; incompatible edits ask for administrator clarification in desktop.

Desktop > Objects > select object > Customer supplements:
use the existing base rate, dated normal/overtime percentages, weekends and
explicit holidays. Empty means unknown; 0% confirms no supplement. Customer
conditions do not change payroll. Evening alone is not overtime.

The Typical schedule tab is optional. Select weekdays, start/end, breaks and
explicit overtime sections. This is a customer calculation assumption, not
employee-reported time. It is never applied automatically, including to old
rows or new web submissions.

Reports and invoicing > Other actions > Preview terms for open records:
review old/new amounts and time source, then explicitly tick the agreed rows.
Hours must match the schedule exactly. OB records and differing shifts require
Clarify in desktop: check actual start/end, breaks and normal/overtime mode.
Time changes are audited and synced. Saved hours, OB categories, transport and
payroll are not changed by applying customer terms or a schedule.

Customer interval calculation and PDF distinguish actual time from an explicitly
confirmed schedule. Closing saves the historical version, base and calculation.
Later object edits do not silently reprice confirmed periods. Closed shifts
remain protected. Correcting actual time clears the old schedule assumption
and requires another review.

The employee form rollback does not roll back useful 1.0.54 invoice, split VAT,
rounding, customer history, closed-period or synchronization protections.

No working databases, originals, credentials or user settings are included.
Keep the previous 1.0.54 installer/application as rollback. Roll back application
files only; never overwrite newer working data with an older database.
